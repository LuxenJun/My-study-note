## 1. 连接与 psql

### 1.1 连接方式

```bash
# 连接串 URI 格式（应用侧最常用）
postgresql://user:pass@host:5432/dbname?sslmode=require

# 命令行参数
psql -h 127.0.0.1 -p 5432 -U postgres -d mydb -W

# 只执行一条语句后退出
psql -c "SELECT version();" -d mydb

# 执行文件后退出
psql -f init.sql -d mydb
```

### 1.2 环境变量与免密

| 变量 | 含义 |
|---|---|
| `PGHOST` / `PGPORT` | 主机 / 端口 |
| `PGUSER` / `PGDATABASE` | 用户 / 数据库 |
| `PGPASSWORD` | 密码（不推荐，会进 shell 历史） |
| `PGSSLMODE` | `disable` / `require` / `verify-full` |

**`.pgpass` 免密文件**（推荐替代 `PGPASSWORD`）：

```
# 格式：hostname:port:database:username:password
127.0.0.1:5432:mydb:postgres:mysecret
*:*:*:postgres:mysecret
```

- Linux/macOS：`~/.pgpass`，权限必须 `chmod 600`
- Windows：`%APPDATA%\postgresql\pgpass.conf`

## 2. 数据类型与建表

### 2.1 类型选型对照

| 场景 | 推荐类型 | 说明 |
|---|---|---|
| 自增主键 | `bigint GENERATED ALWAYS AS IDENTITY` | SQL 标准，优于 `serial` |
| 通用整数 | `integer` / `bigint` | 估算超 21 亿用 `bigint` |
| 金额 | `numeric(12,2)` | **禁用 `float`**，浮点有精度误差 |
| 短文本 | `text` | 与 `varchar` 性能相同，无需限长 |
| 限长文本 | `varchar(n)` | 仅当需要长度约束时 |
| 时间戳 | `timestamptz` | 存 UTC，跨时区唯一正确选择 |
| 日期 | `date` | 无时间部分 |
| 布尔 | `boolean` | 存 `true/false`，不存 0/1 |
| UUID | `uuid` | 生成用 `gen_random_uuid()`；`(PG18+)` 可用 `uuidv7()` |
| 半结构化 | `jsonb` | 可索引、可更新；`json` 只存原文 |
| 多值 | `数组` / `jsonb` | 数组适合定长枚举类 |
| 网络地址 | `inet` / `cidr` / `macaddr` | 原生类型，支持包含运算 |
| 二进制 | `bytea` | 文件、哈希 |

### 2.2 六类约束

```sql
CREATE TABLE users (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email       text        NOT NULL UNIQUE,
    nickname    text        NOT NULL,
    status      text        NOT NULL DEFAULT 'active'
                            CHECK (status IN ('active', 'disabled')),
    balance     numeric(12,2) NOT NULL DEFAULT 0 CHECK (balance >= 0),
    vip         boolean     NOT NULL DEFAULT false,
    created_at  timestamptz NOT NULL DEFAULT now(),
    updated_at  timestamptz NOT NULL DEFAULT now(),
    deleted_at  timestamptz                          -- 软删除标记
);

CREATE TABLE orders (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id     bigint NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    amount      numeric(12,2) NOT NULL,
    status      text NOT NULL DEFAULT 'pending',
    created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX idx_orders_user_created ON orders (user_id, created_at DESC);
```

| 约束 | 作用 | 常用选项 |
|---|---|---|
| `PRIMARY KEY` | 唯一 + 非空 | 复合主键 `(a, b)` |
| `FOREIGN KEY` | 引用完整性 | `ON DELETE CASCADE / SET NULL / RESTRICT` |
| `UNIQUE` | 唯一 | 可加 `NULLS NOT DISTINCT` `(PG15+)` |
| `CHECK` | 行级条件 | 表达式为真才允许写入 |
| `NOT NULL` | 非空 | — |
| `DEFAULT` | 默认值 | `now()` / `gen_random_uuid()` |
| `EXCLUDE` | 排除约束（如时间区间不重叠） | 需 `btree_gist` 扩展 |

### 2.3 主键自增三种方式

```sql
-- ① IDENTITY（推荐）：SQL 标准，权限与序列解耦
id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY
id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY   -- 允许手动插入

-- ② serial：PG 历史写法，本质是 integer + 序列 + DEFAULT
id serial PRIMARY KEY

-- ③ 显式序列：需要跨表共享序列时才用
CREATE SEQUENCE seq_user_id;
id bigint DEFAULT nextval('seq_user_id') PRIMARY KEY

-- 取回序列当前值
SELECT currval('seq_user_id');   -- 当前会话上次取到的值
SELECT last_value FROM seq_user_id;
```

**差异**：`serial` 不检查权限、`IDENTITY` 的序列随列删除自动清理；新项目统一用 `IDENTITY`。

### 2.4 ALTER TABLE 常用操作

```sql
ALTER TABLE users ADD COLUMN phone text;                              -- 加列（可空，瞬时完成）
ALTER TABLE users ADD COLUMN vip boolean NOT NULL DEFAULT false;      -- 加带默认列（PG11+ 不重写全表）
ALTER TABLE users DROP COLUMN phone;                                  -- 删列
ALTER TABLE users ALTER COLUMN nickname TYPE varchar(64) USING nickname::varchar(64);
ALTER TABLE users ALTER COLUMN nickname SET NOT NULL;
ALTER TABLE users ALTER COLUMN nickname DROP NOT NULL;
ALTER TABLE users ALTER COLUMN status SET DEFAULT 'active';
ALTER TABLE users RENAME COLUMN nickname TO display_name;
ALTER TABLE users RENAME TO app_users;

-- 大表加约束：先 NOT VALID 再加，避免长时间锁表
ALTER TABLE orders ADD CONSTRAINT chk_amount CHECK (amount > 0) NOT VALID;
ALTER TABLE orders VALIDATE CONSTRAINT chk_amount;   -- 只持 SHARE UPDATE EXCLUSIVE 锁
```

### 2.5 分区表

```sql
-- 范围分区（时间序列最常用）
-- 注意：普通表无法"转换"为分区表，必须新建；以下为独立示例
CREATE TABLE orders (
    id bigint, user_id bigint, amount numeric(12,2), created_at date
) PARTITION BY RANGE (created_at);

CREATE TABLE orders_2026_01 PARTITION OF orders
    FOR VALUES FROM ('2026-01-01') TO ('2026-02-01');
CREATE TABLE orders_2026_02 PARTITION OF orders
    FOR VALUES FROM ('2026-02-01') TO ('2026-03-01');
CREATE TABLE orders_default PARTITION OF orders DEFAULT;   -- 兜底分区

-- 列表分区
CREATE TABLE orders_by_region (id bigint, region text) PARTITION BY LIST (region);
CREATE TABLE orders_cn PARTITION OF orders_by_region FOR VALUES IN ('cn');
CREATE TABLE orders_us PARTITION OF orders_by_region FOR VALUES IN ('us');

-- 哈希分区（MODULUS = 分片数，REMAINDER = 余数编号）
CREATE TABLE orders_by_hash (id bigint, user_id bigint) PARTITION BY HASH (user_id);
CREATE TABLE orders_h0 PARTITION OF orders_by_hash FOR VALUES WITH (MODULUS 4, REMAINDER 0);

-- 分离与删除分区（秒级，不产生大量 WAL）
ALTER TABLE orders DETACH PARTITION orders_2026_01;
DROP TABLE orders_2026_01;

-- 查看分区
SELECT relname, pg_get_expr(relpartbound, oid) FROM pg_class
WHERE relname LIKE 'orders_%';
```

**约束**：分区键必须出现在主键 / 唯一索引中；分区过多（数百以上）会增加计划耗时。

### 2.6 TRUNCATE / DELETE / DROP 对比

| 操作 | 删除什么 | 可回滚 | 速度 | 锁 |
|---|---|---|---|---|
| `DELETE FROM t` | 行，可带 `WHERE` | ✅ 是 | 慢（逐行、写 WAL） | `ROW EXCLUSIVE` |
| `TRUNCATE t` | 全部行 | ✅ 是 | 快（重建文件） | `ACCESS EXCLUSIVE` |
| `DROP TABLE t` | 表结构 + 数据 | ✅ 是 | 快 | `ACCESS EXCLUSIVE` |

```sql
TRUNCATE orders RESTART IDENTITY CASCADE;   -- 重置自增 + 级联
```

### 2.7 临时表与 UNLOGGED

```sql
CREATE TEMP TABLE tmp_ids (id bigint);              -- 会话级，断开自动删
CREATE UNLOGGED TABLE stage_import (...);           -- 不写 WAL，快，但崩溃后数据清空
```

## 3. DML 核心

### 3.1 INSERT

```sql
-- 单行 / 多行
INSERT INTO users (email, nickname) VALUES ('a@x.com', 'Alice');
INSERT INTO users (email, nickname) VALUES
    ('b@x.com', 'Bob'),
    ('c@x.com', 'Carol');

-- 全默认值
INSERT INTO users DEFAULT VALUES;

-- 从查询结果插入
INSERT INTO users_archive (id, email)
SELECT id, email FROM users WHERE created_at < '2025-01-01';
```

### 3.2 ON CONFLICT（upsert）

```sql
-- 冲突则忽略
INSERT INTO users (email, nickname) VALUES ('a@x.com', 'Alice')
ON CONFLICT (email) DO NOTHING;

-- 冲突则更新（EXCLUDED 代表试图插入的那一行）
INSERT INTO users (email, nickname) VALUES ('a@x.com', 'Alice2')
ON CONFLICT (email) DO UPDATE
SET nickname = EXCLUDED.nickname,
    updated_at = now()
WHERE users.nickname IS DISTINCT FROM EXCLUDED.nickname;   -- 值未变则不写
```

**要点**：`ON CONFLICT` 的冲突目标必须是唯一索引或主键；无索引时只能写 `ON CONFLICT DO NOTHING`（不指定列）。

### 3.3 RETURNING

```sql
INSERT INTO users (email, nickname) VALUES ('d@x.com', 'Dave')
RETURNING id, created_at;                          -- 拿回自增值，避免再查一次

UPDATE orders SET status = 'paid' WHERE id = 100
RETURNING id, status;

DELETE FROM orders WHERE created_at < '2020-01-01'
RETURNING id;
```

### 3.4 UPDATE ... FROM / DELETE ... USING

```sql
-- 用另一张表的值更新（比相关子查询快）
UPDATE orders o
SET amount = o.amount * 1.1
FROM users u
WHERE o.user_id = u.id AND u.vip = true;

-- 关联删除
DELETE FROM orders o
USING users u
WHERE o.user_id = u.id AND u.status = 'disabled';
```

### 3.5 MERGE (PG15+)

```sql
MERGE INTO users t
USING staging_users s ON t.email = s.email
WHEN MATCHED AND s.deleted THEN DELETE
WHEN MATCHED THEN UPDATE SET nickname = s.nickname
WHEN NOT MATCHED THEN INSERT (email, nickname) VALUES (s.email, s.nickname);
```

### 3.6 批量导入与造数

```sql
-- 服务端 COPY：最快，文件必须在服务器上，且需超级用户或 pg_read_server_files 角色
COPY orders FROM '/data/orders.csv' WITH (FORMAT csv, HEADER true);
COPY orders TO '/data/out.csv' WITH (FORMAT csv, HEADER true);

-- 造 100 万条测试数据
INSERT INTO orders (user_id, amount, created_at)
SELECT (random() * 999 + 1)::bigint,
       (random() * 1000)::numeric(12,2),
       now() - (random() * interval '365 days')
FROM generate_series(1, 1000000);

-- 生成连续日期 / 数字
SELECT d::date FROM generate_series('2026-01-01'::date, '2026-12-31'::date, '1 day') d;
SELECT n FROM generate_series(1, 10) n;
```

**导入性能**：大批量写入前可 `SET synchronous_commit = off;`、去掉索引后再建，比逐条 INSERT 快一个数量级。

## 4. 查询进阶

### 4.1 逻辑执行顺序

书写顺序与实际求值顺序不同，这解释了为什么 `WHERE` 里不能用 `SELECT` 的别名：

```
FROM / JOIN  →  WHERE  →  GROUP BY  →  HAVING  →  窗口函数
            →  SELECT（列与别名）  →  DISTINCT  →  ORDER BY  →  LIMIT / OFFSET
```

```sql
-- ❌ 报错：WHERE 阶段别名尚不存在
SELECT amount * 1.1 AS total FROM orders WHERE total > 100;

-- ✅ 用子查询或 CTE 包裹
SELECT * FROM (SELECT amount * 1.1 AS total FROM orders) t WHERE t.total > 100;
```

### 4.2 JOIN

```sql
SELECT o.id, u.email
FROM orders o
JOIN users u ON u.id = o.user_id;              -- INNER JOIN：两表都匹配

SELECT u.email, o.id
FROM users u
LEFT JOIN orders o ON o.user_id = u.id;        -- LEFT：左表全保留，右表无匹配补 NULL

-- FULL JOIN：两侧都保留
-- CROSS JOIN：笛卡尔积（生成组合场景）
-- LATERAL：右侧子查询可引用左侧当前行的列
SELECT u.email, x.last_order_at
FROM users u
LEFT JOIN LATERAL (
    SELECT max(created_at) AS last_order_at
    FROM orders o WHERE o.user_id = u.id
) x ON true;
```

**经典错误**：`LEFT JOIN` 后把右表条件写进 `WHERE`，会把外连接退化成内连接——条件应写在 `ON` 里。

```sql
-- ❌ 退化
LEFT JOIN orders o ON o.user_id = u.id WHERE o.status = 'paid'
-- ✅ 保留未下单用户
LEFT JOIN orders o ON o.user_id = u.id AND o.status = 'paid'
```

### 4.3 聚合

```sql
SELECT status,
       count(*)                                    AS cnt,
       count(DISTINCT user_id)                     AS user_cnt,
       sum(amount)                                 AS total,
       round(avg(amount), 2)                       AS avg_amt,
       min(created_at), max(created_at)
FROM orders
GROUP BY status
HAVING count(*) > 10
ORDER BY total DESC;
```

**`FILTER` 子句**：一次扫描算出多个条件统计，替代多个子查询。

```sql
SELECT user_id,
       count(*) FILTER (WHERE status = 'paid')    AS paid_cnt,
       count(*) FILTER (WHERE status = 'pending') AS pending_cnt,
       sum(amount) FILTER (WHERE status = 'paid') AS paid_amount
FROM orders
GROUP BY user_id;
```

**多维度汇总**：

```sql
SELECT status, date_trunc('month', created_at) AS mon, sum(amount)
FROM orders
GROUP BY ROLLUP (status, date_trunc('month', created_at));
-- GROUPING SETS ((a),(b),()) 精确指定组合；CUBE 生成全组合
```

### 4.4 窗口函数

```sql
-- 通用结构
函数() OVER (PARTITION BY 分组列 ORDER BY 排序列 帧子句)
```

| 函数 | 作用 |
|---|---|
| `row_number()` | 组内连续序号（1,2,3） |
| `rank()` | 并列跳号（1,1,3） |
| `dense_rank()` | 并列不跳号（1,1,2） |
| `lag(col, n)` / `lead(col, n)` | 取前 / 后第 n 行 |
| `first_value` / `last_value` / `nth_value` | 帧内首 / 末 / 第 n 个 |
| `sum/avg/count ... OVER` | 累计或滑动聚合 |
| `ntile(n)` | 分 n 桶 |
| `percent_rank()` / `cume_dist()` | 百分位 |

**场景一：每组取最新一条**

```sql
-- 写法 A：DISTINCT ON（PG 特色，通常最快）
SELECT DISTINCT ON (user_id) user_id, id, amount, created_at
FROM orders
ORDER BY user_id, created_at DESC;

-- 写法 B：row_number（需要更多列或复杂条件时用）
SELECT * FROM (
    SELECT *, row_number() OVER (PARTITION BY user_id ORDER BY created_at DESC) AS rn
    FROM orders
) t WHERE rn = 1;
```

**场景二：累计求和**

```sql
SELECT created_at::date AS d,
       amount,
       sum(amount) OVER (ORDER BY created_at
                         ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total
FROM orders;
```

**场景三：环比**

```sql
WITH monthly AS (
    SELECT date_trunc('month', created_at) AS mon, sum(amount) AS amt
    FROM orders GROUP BY 1
)
SELECT mon, amt,
       lag(amt) OVER (ORDER BY mon)           AS prev_amt,
       round((amt - lag(amt) OVER (ORDER BY mon)) * 100.0
             / nullif(lag(amt) OVER (ORDER BY mon), 0), 2) AS growth_pct
FROM monthly ORDER BY mon;
```

**场景四：分组内去重排名 + 取前 N**

```sql
SELECT * FROM (
    SELECT user_id, id, amount,
           dense_rank() OVER (PARTITION BY user_id ORDER BY amount DESC) AS rk
    FROM orders
) t WHERE rk <= 3;
```

**帧子句速记**：

- `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` — 从首行到当前行（累计）
- `ROWS BETWEEN 6 PRECEDING AND CURRENT ROW` — 近 7 行滑动
- `RANGE BETWEEN INTERVAL '7 days' PRECEDING AND CURRENT ROW` — 按时间滑动（需 ORDER BY 时间列）
- 不写帧子句时，有 `ORDER BY` 默认 `RANGE UNBOUNDED PRECEDING TO CURRENT ROW`

### 4.5 CTE 与递归

```sql
-- 普通 CTE：拆解复杂查询
WITH paid AS (
    SELECT * FROM orders WHERE status = 'paid'
), agg AS (
    SELECT user_id, sum(amount) AS total FROM paid GROUP BY user_id
)
SELECT u.email, a.total
FROM agg a JOIN users u ON u.id = a.user_id;

-- 强制物化 / 强制内联 (PG12+)
WITH x AS MATERIALIZED (SELECT ...) SELECT ...;
WITH x AS NOT MATERIALIZED (SELECT ...) SELECT ...;

-- 递归 CTE：树形结构展开
WITH RECURSIVE tree AS (
    SELECT id, parent_id, name, 1 AS depth
    FROM categories WHERE parent_id IS NULL
    UNION ALL
    SELECT c.id, c.parent_id, c.name, t.depth + 1
    FROM categories c JOIN tree t ON c.parent_id = t.id
    WHERE t.depth < 10                     -- 必须有终止条件，否则无限递归
)
SELECT * FROM tree ORDER BY depth, id;
```

### 4.6 EXISTS / IN / JOIN 的差异

```sql
-- EXISTS：半连接，找到第一条即短路，大表首选
SELECT * FROM users u
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);

-- IN：结果集较小时可读性好；子查询含 NULL 时 NOT IN 会返回空结果
SELECT * FROM users WHERE id IN (SELECT user_id FROM orders);

-- ❌ 致命写法：orders.user_id 中只要有 NULL，整个查询返回 0 行
SELECT * FROM users WHERE id NOT IN (SELECT user_id FROM orders);

-- ✅ 改用 NOT EXISTS
SELECT * FROM users u
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);
```

| 写法 | 语义 | 适用 |
|---|---|---|
| `JOIN` | 需返回两表列，可能产生重复行 | 要右表字段 |
| `EXISTS` | 只判断存在性，短路 | 大表、`NOT` 场景 |
| `IN` | 集合成员判断 | 小结果集、字面量列表 |

### 4.7 集合运算

```sql
SELECT id FROM orders_2025
UNION          -- 去重 + 排序，较慢
SELECT id FROM orders_2026;

SELECT id FROM orders_2025
UNION ALL      -- 不去重，最快，能用就用它
SELECT id FROM orders_2026;

INTERSECT      -- 交集
EXCEPT         -- 差集（左侧有、右侧无）
```

**注意**：集合运算按**列位置**对齐，不看列名；列类型需兼容。

## 5. 函数速查

### 5.1 字符串

| 需求 | 函数 |
|---|---|
| 拼接 | `a \|\| b`、`concat(a,b)`、`concat_ws(',', a, b)` |
| 长度 | `length(s)`（字符）、`octet_length(s)`（字节） |
| 截取 | `substr(s, 2, 3)`、`left(s,3)`、`right(s,3)` |
| 分割 | `split_part(s, ',', 2)`（取第 2 段，下标从 1 开始） |
| 聚合拼接 | `string_agg(col, ',' ORDER BY col)` |
| 替换 | `replace(s,'a','b')`、`regexp_replace(s, '\d+', '#', 'g')` |
| 查找位置 | `position('ab' IN s)`、`strpos(s,'ab')` |
| 大小写 | `upper` / `lower` / `initcap` |
| 去空白 | `trim(s)`、`btrim(s, 'xy')`、`ltrim` / `rtrim` |
| 填充 | `lpad(s, 5, '0')`、`rpad(s, 5, ' ')` |
| 重复 / 反转 | `repeat(s, 3)`、`reverse(s)` |
| 正则提取 | `regexp_match(s, '(\d+)')`、`regexp_matches(s,'\d+','g')` |
| 正则拆分 | `regexp_split_to_array(s, ',')`、`regexp_split_to_table(s, ',')` |
| 哈希 | `md5(s)`、`encode(sha256(s::bytea), 'hex')` |

```sql
-- 模糊匹配
WHERE email ILIKE '%@gmail.com'          -- 忽略大小写
WHERE name LIKE 'A\_%' ESCAPE '\'        -- 转义下划线
WHERE name ~ '^A.*n$'                    -- POSIX 正则
WHERE name ~* '^a'                       -- 正则忽略大小写
WHERE name !~ '^A'                       -- 正则不匹配
```

### 5.2 时间与日期

| 需求 | 写法 |
|---|---|
| 当前时间 | `now()`（事务内固定）、`clock_timestamp()`（实时） |
| 当前日期 | `current_date`、`current_timestamp` |
| 截断 | `date_trunc('month', ts)` — `year/quarter/month/week/day/hour/minute` |
| 提取 | `extract(year FROM ts)`、`date_part('dow', ts)` |
| 时间差 | `ts2 - ts1`（interval）、`age(ts2, ts1)`（人类可读） |
| 加减 | `ts + interval '1 day'`、`ts - interval '30 minutes'` |
| 转字符串 | `to_char(ts, 'YYYY-MM-DD HH24:MI:SS')` |
| 字符串转时间 | `to_timestamp('2026-01-01', 'YYYY-MM-DD')`、`'2026-01-01'::date` |
| 时区转换 | `ts AT TIME ZONE 'Asia/Shanghai'` |
| 构造 | `make_date(2026,1,1)`、`make_interval(days => 7)` |
| 月初 / 周末 | `date_trunc('month', ts)`、`date_trunc('week', ts) + interval '6 days'` |

```sql
-- 常用时间范围条件（能走索引的写法）
WHERE created_at >= date_trunc('day', now())
  AND created_at <  date_trunc('day', now()) + interval '1 day'
```

**`to_char` 格式符**：

| 符 | 含义 | 符 | 含义 |
|---|---|---|---|
| `YYYY` | 4 位年 | `HH24` | 24 小时制 |
| `MM` | 月 01-12 | `MI` | 分 |
| `DD` | 日 01-31 | `SS` | 秒 |
| `DOW` | 星期 0-6 | `MS` | 毫秒 |
| `Q` | 季度 | `IW` | ISO 周数 |

```sql
SELECT to_char(now(), 'YYYY-MM-DD HH24:MI:SS');       -- 2026-11-11 21:00:00
SELECT to_char(now(), 'YYYY"年"MM"月"DD"日"');         -- 中文字面量用双引号包裹
```

### 5.3 JSONB

**操作符**：

| 操作符 | 返回 | 说明 |
|---|---|---|
| `data -> 'a'` | `jsonb` | 取对象键 / 数组下标（结果仍是 jsonb） |
| `data ->> 'a'` | `text` | 同上，但返回文本 |
| `data #> '{a,b}'` | `jsonb` | 按路径取 |
| `data #>> '{a,b}'` | `text` | 按路径取，返回文本 |
| `data @> '{"a":1}'` | `boolean` | 左侧是否包含右侧 |
| `data <@ '{"a":1}'` | `boolean` | 左侧是否被右侧包含 |
| `data ? 'a'` | `boolean` | 顶层键 / 数组元素是否存在 |
| `data ?\| ARRAY['a','b']` | `boolean` | 任一存在 |
| `data ?& ARRAY['a','b']` | `boolean` | 全部存在 |
| `a \|\| b` | `jsonb` | 合并（后者覆盖同名键） |
| `data - 'a'` / `- 0` | `jsonb` | 删键 / 删数组元素 |
| `data #- '{a,b}'` | `jsonb` | 删路径 |

**函数**：

```sql
jsonb_build_object('k', 1)                  -- {"k": 1}
to_jsonb(row)                               -- 行转 jsonb
jsonb_agg(col)                              -- 聚合为数组
jsonb_object_agg(k, v)                      -- 聚合为对象
jsonb_array_elements(data -> 'items')       -- 展开数组为多行
jsonb_each(data)                            -- 展开对象为 (key, value) 多行
jsonb_each_text(data)                       -- 同上，值为 text
jsonb_object_keys(data)                     -- 键列表
jsonb_set(data, '{a,b}', '1', true)         -- 设置路径（true = 不存在则创建）
jsonb_insert(data, '{a,0}', '"x"')          -- 数组插入
jsonb_strip_nulls(data)                     -- 去空值键
jsonb_typeof(data)                          -- object/array/string/number/boolean/null
jsonb_pretty(data)                          -- 格式化输出
jsonb_path_query(data, '$.items[*] ? (@.price > 100)')   -- SQL/JSON 路径
jsonb_path_exists(data, '$.a ? (@ > 1)')
```

**示例**：

```sql
-- 表结构：CREATE TABLE events (id bigint, payload jsonb);
INSERT INTO events (payload) VALUES ('{"user":{"id":7},"tags":["a","b"],"amount":120}');

SELECT payload ->> 'amount' AS amount,                   -- "120"（text）
       (payload ->> 'amount')::numeric AS amount_num,
       payload #>> '{user,id}'      AS user_id
FROM events;

-- 包含查询（走 GIN 索引）
SELECT * FROM events WHERE payload @> '{"user":{"id":7}}';

-- 键存在
SELECT * FROM events WHERE payload ? 'tags';

-- 展开数组做行转列
SELECT id, t.tag
FROM events, jsonb_array_elements_text(payload -> 'tags') AS t(tag);

-- 建 GIN 索引
CREATE INDEX idx_events_payload ON events USING gin (payload jsonb_path_ops);
```

**要点**：`->` 与 `->>` 混用是最常见 bug——`payload -> 'amount' = '120'` 恒为假（jsonb vs text 比较），必须写 `payload ->> 'amount' = '120'`。

**`JSON_TABLE`** `(PG17+)`：把 JSON 按 SQL/JSON 标准展平成关系表。

```sql
SELECT jt.*
FROM events,
     JSON_TABLE (payload, '$.tags[*]'
                 COLUMNS (tag text PATH '$')) AS jt;
```

## 6. 索引与执行计划

### 6.1 五种索引类型

| 类型 | 适用 | 支持运算 |
|---|---|---|
| **B-tree**（默认） | 等值、范围、排序、前缀匹配 | `= < <= > >= BETWEEN IN` `ORDER BY` |
| **Hash** | 仅等值，比 B-tree 略小 | `=` |
| **GIN** | 多值：数组、`jsonb`、全文检索、`pg_trgm` | `@> ? ?& &&`、`@@`、`LIKE '%x%'`(trgm) |
| **GiST** | 几何、范围类型、近邻、排除约束 | `&& << >> @>`、`<->` |
| **BRIN** | 超大表 + 物理有序（时间序列） | 范围（索引体积极小） |

```sql
CREATE INDEX idx_orders_created   ON orders (created_at);                     -- B-tree
CREATE INDEX idx_orders_hash      ON orders USING hash (status);              -- Hash
CREATE INDEX idx_events_payload   ON events USING gin (payload jsonb_path_ops);-- GIN
CREATE INDEX idx_orders_brin      ON orders USING brin (created_at);          -- BRIN
```

### 6.2 索引变体

```sql
-- 复合索引：列顺序决定可用范围（最左前缀原则）
CREATE INDEX idx_orders_user_time ON orders (user_id, created_at DESC);

-- 部分索引：只索引活跃数据，体积小、写代价低
CREATE INDEX idx_orders_pending ON orders (created_at)
WHERE status = 'pending';

-- 表达式索引：让函数条件也能走索引
CREATE INDEX idx_users_lower_email ON users (lower(email));
SELECT * FROM users WHERE lower(email) = 'a@x.com';   -- 能用上

-- 覆盖索引：把查询列放进索引，避免回表 (PG11+)
CREATE INDEX idx_orders_cover ON orders (user_id) INCLUDE (amount, status);

-- 唯一索引 + 条件（可做"软删除唯一"）
CREATE UNIQUE INDEX uq_users_email_active ON users (email) WHERE deleted_at IS NULL;

-- 不锁表建索引（生产必备）
CREATE INDEX CONCURRENTLY idx_orders_amount ON orders (amount);
-- 注意：CONCURRENTLY 不能在事务块内执行；失败会留下 INVALID 索引，需 DROP 后重建

-- 查看索引使用情况
SELECT indexrelname, idx_scan, idx_tup_read
FROM pg_stat_user_indexes
WHERE relname = 'orders' ORDER BY idx_scan;
-- idx_scan = 0 且非唯一索引 → 可考虑删除
```

### 6.3 索引失效的 8 种情形

| # | 情形 | 反例 | 正确写法 |
|---|---|---|---|
| 1 | 列被函数包裹 | `WHERE lower(email)='a'` | 建表达式索引 |
| 2 | 隐式类型转换 | `WHERE bigint_col = '123'` | 保持两侧同类型 |
| 3 | 前导通配符 | `LIKE '%abc'` | 用 `pg_trgm` + GIN |
| 4 | 不等 / 否定 | `WHERE status <> 'x'` | 改写成 `IN` 或部分索引 |
| 5 | `OR` 混合不同列 | `WHERE a=1 OR b=2` | 拆成 `UNION ALL` |
| 6 | 空值比例高 | `WHERE col IS NULL` | 部分索引 |
| 7 | 统计信息过期 | 大批量写入后计划突变 | `ANALYZE` |
| 8 | 复合索引跳过最左列 | 索引 `(a,b)` 但只查 `b` | 建 `(b)` 或调整列序 |

### 6.4 EXPLAIN 读法

```sql
EXPLAIN SELECT * FROM orders WHERE user_id = 7;

EXPLAIN (ANALYZE, BUFFERS, VERBOSE)     -- 实际执行并采集真实耗时与 I/O
SELECT * FROM orders WHERE user_id = 7;
```

**输出结构**：

```
Index Scan using idx_orders_user_time on orders
  (cost=0.43..8.45 rows=1 width=48) (actual time=0.021..0.023 rows=3 loops=1)
  Index Cond: (user_id = 7)
  Buffers: shared hit=4
Planning Time: 0.120 ms
Execution Time: 0.045 ms
```

| 字段 | 含义 |
|---|---|
| `cost=start..total` | **估算**的启动代价..总代价（任意单位，用于比较计划优劣） |
| `rows` | 估算返回行数（**与实际差距大 = 统计信息问题**） |
| `width` | 单行平均字节 |
| `actual time` | 真实耗时（`ANALYZE` 才有） |
| `loops` | 该节点被执行次数，实际代价需 `actual time × loops` |
| `Buffers: shared hit` | 命中共享缓冲区（内存）页数 |
| `Buffers: shared read` | 从磁盘读取页数（`read` 高 = 缓存不足或首次访问） |
| `Rows Removed by Filter` | 被过滤掉的行数，越大说明扫描浪费越多 |

**四种扫描方式识别**：

| 节点 | 含义 | 何时出现 |
|---|---|---|
| `Seq Scan` | 全表顺序扫描 | 无索引、或返回比例过大（>5%~10%） |
| `Index Scan` | 走索引 + 回表取行 | 返回少量行 |
| `Index Only Scan` | 只读索引不回表 | 覆盖索引 + `visibility map` 干净（需 `VACUUM`） |
| `Bitmap Index Scan` + `Bitmap Heap Scan` | 先建位图再批量回表 | 中等比例返回、多条件组合 |

**连接方式**：

- `Nested Loop`：小表驱动大表，有索引时最优
- `Hash Join`：大表对大表，无索引等值连接
- `Merge Join`：两侧都有序（索引序或已排序）

**诊断动作**：

```sql
ANALYZE orders;                       -- 更新单表统计信息
ANALYZE;                              -- 全库
VACUUM (ANALYZE, VERBOSE) orders;     -- 回收死元组 + 更新统计
```

## 7. 慢查询与锁排查

> 以下 SQL 可直接复制执行，按需替换表名。

### 7.1 当前活动会话（按耗时排序）

```sql
SELECT pid,
       usename,
       datname,
       state,
       wait_event_type,
       wait_event,
       now() - query_start AS duration,
       left(query, 120)    AS query_snippet
FROM pg_stat_activity
WHERE state <> 'idle'
ORDER BY duration DESC;
```

`state` 常见值：`active`（执行中）、`idle`（空闲）、`idle in transaction`（**事务未提交，高危**）。

### 7.2 Top SQL（pg_stat_statements）

```sql
-- 一次性启用（需重启）
ALTER SYSTEM SET shared_preload_libraries = 'pg_stat_statements';
-- postgresql.conf 中同时建议：pg_stat_statements.track = all

CREATE EXTENSION IF NOT EXISTS pg_stat_statements;

-- PG13+ 字段名为 total_exec_time；PG12 及以前为 total_time
SELECT round(total_exec_time::numeric, 2) AS total_ms,
       calls,
       round(mean_exec_time::numeric, 2)  AS mean_ms,
       rows,
       left(query, 100)                   AS query
FROM pg_stat_statements
ORDER BY total_exec_time DESC
LIMIT 20;

-- 重置统计
SELECT pg_stat_statements_reset();
```

### 7.3 锁与阻塞链

```sql
-- 当前未授予的锁（谁在等）
SELECT a.pid, a.usename, l.locktype, l.mode, l.relation::regclass, left(a.query, 80)
FROM pg_locks l
JOIN pg_stat_activity a ON a.pid = l.pid
WHERE NOT l.granted;

-- 阻塞链：谁挡住了谁（PG9.6+）
SELECT pid,
       pg_blocking_pids(pid) AS blocked_by,
       state,
       left(query, 100)      AS query
FROM pg_stat_activity
WHERE cardinality(pg_blocking_pids(pid)) > 0;

-- 表上的锁明细
SELECT l.pid, l.mode, l.granted, a.state, left(a.query, 80)
FROM pg_locks l JOIN pg_stat_activity a ON a.pid = l.pid
WHERE l.relation = 'orders'::regclass;
```

### 7.4 终止会话

```sql
SELECT pg_cancel_backend(12345);      -- 取消当前查询，保留连接（优先用这个）
SELECT pg_terminate_backend(12345);   -- 强制断开连接，事务回滚

-- 批量清理长时间空闲事务（谨慎）
SELECT pg_terminate_backend(pid)
FROM pg_stat_activity
WHERE state = 'idle in transaction'
  AND now() - state_change > interval '10 minutes';
```

### 7.5 体积与膨胀

```sql
-- 表 / 索引 / 总大小 Top 20
SELECT relname,
       pg_size_pretty(pg_total_relation_size(oid)) AS total,
       pg_size_pretty(pg_relation_size(oid))       AS heap,
       pg_size_pretty(pg_indexes_size(oid))        AS indexes,
       n_live_tup, n_dead_tup,
       round(100.0 * n_dead_tup / nullif(n_live_tup + n_dead_tup, 0), 1) AS dead_pct
FROM pg_class c
LEFT JOIN pg_stat_user_tables s ON s.relid = c.oid
WHERE c.relkind = 'r'
ORDER BY pg_total_relation_size(oid) DESC
LIMIT 20;

-- 数据库大小
SELECT datname, pg_size_pretty(pg_database_size(datname)) FROM pg_database ORDER BY 2 DESC;
```

`n_dead_tup` 占比长期 >20% 说明 autovacuum 跟不上，需调 `autovacuum_vacuum_scale_factor` 或对热点表单独设置。

### 7.6 缓存命中率与连接数

## 8. 事务与并发

### 8.1 基本语法

```sql
BEGIN;                                  -- 或 START TRANSACTION
UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;
COMMIT;                                 -- 或 ROLLBACK

-- 保存点：部分回滚
BEGIN;
INSERT INTO orders (user_id, amount) VALUES (1, 100);
SAVEPOINT sp1;
INSERT INTO orders (user_id, amount) VALUES (2, 200);
ROLLBACK TO SAVEPOINT sp1;              -- 只撤销 sp1 之后的
COMMIT;                                 -- 第一条插入仍生效
```

### 8.2 隔离级别

```sql
BEGIN ISOLATION LEVEL REPEATABLE READ;
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
```

| 级别 | PG 实际行为 | 幻读 | 序列化失败 |
|---|---|---|---|
| `READ UNCOMMITTED` | **等同** `READ COMMITTED`（PG 不存在脏读） | 可能 | 无 |
| `READ COMMITTED`（默认） | 每条语句取**语句开始时**的快照 | 可能 | 无 |
| `REPEATABLE READ` | 事务内快照固定（快照隔离） | **不会** | 可能（更新冲突报 `40001`） |
| `SERIALIZABLE` | SSI 串行化快照隔离 | 不会 | 较常见（`40001`，需重试） |

**实践**：默认 `READ COMMITTED` 足够；需要对账、报表一致性用 `REPEATABLE READ`；`SERIALIZABLE` 必须配应用层重试逻辑。

### 8.3 行锁

```sql
-- 悲观锁：锁住选中行直到事务结束
SELECT * FROM orders WHERE id = 100 FOR UPDATE;

-- 不等待，拿不到锁直接报错（适合快速失败）
SELECT * FROM orders WHERE id = 100 FOR UPDATE NOWAIT;

-- 跳过已被锁的行（队列消费标准范式）
BEGIN;
SELECT id FROM jobs
WHERE status = 'pending'
ORDER BY id
LIMIT 1
FOR UPDATE SKIP LOCKED;
UPDATE jobs SET status = 'running' WHERE id = ...;
COMMIT;

-- 共享锁（允许他人也加共享锁，禁止排他）
SELECT * FROM orders WHERE id = 100 FOR SHARE;
```

| 子句 | 行为 |
|---|---|
| `FOR UPDATE` | 排他行锁 + 阻塞写 |
| `FOR NO KEY UPDATE` | 排他但允许外键引用（更轻） |
| `FOR SHARE` | 共享锁，阻塞写不阻塞读 |
| `NOWAIT` | 立即失败而非排队 |
| `SKIP LOCKED` | 跳过锁定行，返回其余 |

### 8.4 死锁

PG 会自动检测环形等待，**回滚其中一个事务**并报错：

```
ERROR:  deadlock detected
DETAIL:  Process 123 waits for ShareLock on transaction 456; blocked by process 456.
HINT:  See server log for query details.
SQLSTATE: 40P01
```

**预防**：多个表 / 多行加锁时，**统一按主键升序访问**，消除环形等待。

### 8.5 长事务与 MVCC

```sql
-- 找出长事务
SELECT pid, usename, state, now() - xact_start AS xact_age, left(query, 80)
FROM pg_stat_activity
WHERE xact_start IS NOT NULL
ORDER BY xact_age DESC
LIMIT 10;

-- 复制槽阻塞 WAL 回收（易被忽视）
SELECT slot_name, active, pg_size_pretty(pg_wal_lsn_diff(pg_current_wal_lsn(), restart_lsn))
FROM pg_replication_slots;
```

**机制**：`UPDATE` 不原地修改，而是写入新版本行，旧版本标记为死元组，由 `VACUUM` 回收。**长事务（尤其是 `idle in transaction`）会阻止 VACUUM 回收其快照之后的所有死元组**，导致表与索引持续膨胀。这是生产库最常见的隐性性能退化原因。

```sql
VACUUM orders;                  -- 常规回收，不锁表
VACUUM FULL orders;             -- 重写表，ACCESS EXCLUSIVE 锁，大表慎用
VACUUM (VERBOSE, ANALYZE) orders;
```

大表回收空间优先用 `pg_repack` 扩展（在线重写，仅短暂锁）。

## 9. 权限管理

### 9.1 角色

```sql
CREATE ROLE app_user LOGIN PASSWORD 'strong_pwd';       -- 可登录角色
CREATE ROLE readonly  LOGIN PASSWORD 'strong_pwd';
CREATE ROLE analyst   NOLOGIN;                          -- 仅用于分组授权

-- 角色继承（成员自动获得组权限）
GRANT analyst TO app_user;

ALTER ROLE app_user SET statement_timeout = '30s';      -- 角色级默认参数
ALTER ROLE app_user SET search_path = app, public;
ALTER ROLE app_user VALID UNTIL '2027-01-01';

DROP ROLE app_user;
```

### 9.2 分级授权

```sql
-- 数据库层
GRANT CONNECT ON DATABASE mydb TO app_user;

-- 模式层（进不去 schema 就看不到表）
GRANT USAGE ON SCHEMA public TO app_user;
GRANT CREATE ON SCHEMA app TO app_user;

-- 表层（ALL TABLES 只影响已存在的表）
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_user;

-- 单表 / 单列
GRANT SELECT ON orders TO app_user;
GRANT UPDATE (status) ON orders TO app_user;            -- 只允许改某列

-- 序列表层（IDENTITY / serial 必须授权，否则插入失败）
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO app_user;

-- 函数层
GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA public TO app_user;

-- 收回
REVOKE DELETE ON orders FROM app_user;
```

### 9.3 默认权限（管住未来新建的表）

`GRANT ... ON ALL TABLES` 只对**执行时刻已存在**的表生效。新建表必须靠默认权限：

```sql
ALTER DEFAULT PRIVILEGES IN SCHEMA public
    GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO app_user;

ALTER DEFAULT PRIVILEGES IN SCHEMA public
    GRANT USAGE, SELECT ON SEQUENCES TO app_user;
```

**注意**：`ALTER DEFAULT PRIVILEGES` 只对**执行者本人**之后创建的对象生效。若建表由 `migration_user` 执行，就必须以该角色身份执行这条语句。

### 9.4 只读账号标准配方

```sql
CREATE ROLE readonly LOGIN PASSWORD 'strong_pwd';
GRANT CONNECT ON DATABASE mydb TO readonly;
GRANT USAGE ON SCHEMA public TO readonly;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO readonly;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO readonly;

-- 双保险：会话级只读
ALTER ROLE readonly SET default_transaction_read_only = on;
```

### 9.5 pg_hba.conf

```
# TYPE  DATABASE  USER      ADDRESS         METHOD
local   all       postgres                  peer
host    all       all       127.0.0.1/32    scram-sha-256
host    all       all       10.0.0.0/8      scram-sha-256
```

修改后重载：`SELECT pg_reload_conf();` 或 `pg_ctl reload`。

**安全基线**：禁止 `trust` 认证；`postgresql.conf` 中 `listen_addresses` 不要写 `*` 除非确有必要；优先 `scram-sha-256`（`md5` 已不推荐）。

## 10. 备份与恢复

### 10.1 pg_dump 格式选择

| 格式 | 参数 | 特点 |
|---|---|---|
| 纯 SQL | `-Fp`（默认） | 可读，用 `psql` 恢复，**不能并行** |
| 自定义 | `-Fc` | 压缩，`pg_restore` 可选择性恢复，**推荐** |
| 目录 | `-Fd` | 支持 `-j` 并行，**大库首选** |
| tar | `-Ft` | 归档为单文件，灵活性差 |

```bash
# 自定义格式（最常用）
pg_dump -h localhost -U postgres -d mydb -Fc -f mydb_$(date +%F).dump

# 目录格式 + 4 并行（大库）
pg_dump -h localhost -U postgres -d mydb -Fd -j 4 -f /backup/mydb_dir

# 纯 SQL
pg_dump -h localhost -U postgres -d mydb -Fp -f mydb.sql

# 只导结构 / 只导数据
pg_dump -s -d mydb -f schema.sql
pg_dump -a -d mydb -f data.sql

# 只导指定表
pg_dump -d mydb -t 'orders*' -Fc -f orders.dump

# 导出所有角色与表空间（不含数据）
pg_dumpall -g -f globals.sql
```

### 10.2 pg_restore

```bash
# 建库后恢复
createdb -h localhost -U postgres mydb_new
pg_restore -h localhost -U postgres -d mydb_new -Fc mydb.dump

# 并行 + 先清理已有对象
pg_restore -d mydb -j 4 -c mydb.dump

# 只恢复某张表
pg_restore -d mydb -t orders mydb.dump

# 只恢复到某个 schema
pg_restore -d mydb -n public mydb.dump

# 列出归档内容（不恢复）
pg_restore -l mydb.dump

# 纯 SQL 恢复
psql -h localhost -U postgres -d mydb -f mydb.sql
```

### 10.3 物理备份

```bash
# 基础备份（全量物理），需 wal_level = replica
pg_basebackup -h localhost -U replicator -D /backup/base -Ft -z -P

# 流式从库初始化
pg_basebackup -h primary -D /var/lib/pgsql/data -Xs -P -R   # -R 自动写 recovery 配置
```

### 10.4 COPY vs \copy

| | `COPY` | `\copy` |
|---|---|---|
| 执行位置 | **服务端** | **客户端** |
| 文件路径 | 服务器上的路径 | 本机路径 |
| 权限 | 需超级用户或 `pg_read_server_files` | 普通用户即可 |
| 语法 | SQL 语句 | psql 元命令 |

```sql
-- 服务端
COPY orders (id, user_id, amount) FROM '/data/o.csv' WITH (FORMAT csv, HEADER true, DELIMITER ',');
COPY orders TO STDOUT WITH CSV HEADER;      -- 输出到客户端（psql 下可重定向）
```

```bash
# 客户端
\copy orders TO 'o.csv' WITH CSV HEADER
\copy orders FROM 'o.csv' WITH CSV HEADER
```

### 10.5 PITR（时间点恢复）三步

```
① 开启归档
   postgresql.conf:
     wal_level = replica
     archive_mode = on
     archive_command = 'cp %p /archive/%f'

② 准备全量基础备份
   pg_basebackup -D /backup/base -Ft -z -P

③ 恢复：还原基础备份 → 配置 restore_command → 设定恢复目标 → 启动
   restore_command = 'cp /archive/%f %p'
   recovery_target_time = '2026-11-11 20:00:00+08'
   recovery_target_action = 'promote'      -- PG12+
   然后在数据目录创建 recovery.signal 空文件，启动即进入恢复
```

**要点**：PITR 的必要条件是「基础备份 + 从该备份起始点开始的全量 WAL 归档」，缺任一段都无法恢复到目标时刻。

## 11. 高频陷阱 20 条

> 格式：**症状** → 原因 → 正确做法

**1. 时间莫名差 8 小时**
`timestamp` 不带时区、不存时区信息；`timestamptz` 内部存 UTC 并在输出时按会话时区转换。→ 统一用 `timestamptz`，应用层传带时区的 ISO 8601 字符串。

**2. 建表后查询报"列不存在"**
未加引号的标识符会被折叠为小写，`CREATE TABLE "User"` 与 `SELECT * FROM User` 不是同一个对象。→ 别用大写和保留字命名，必须用时全程加双引号。

**3. 单双引号混用报错**
单引号是字符串字面量，双引号是标识符。`WHERE name = "Alice"` 会被当成列名。→ 字符串一律单引号。

**4. `WHERE col = NULL` 查不到数据**
任何值与 NULL 比较结果都是 NULL（不是 true）。→ 用 `IS NULL` / `IS NOT NULL`；需要"视为相等"时用 `IS NOT DISTINCT FROM`。

**5. `NOT IN` 子查询返回空结果**
子查询结果含 NULL 时，`NOT IN` 整体恒为假。→ 改 `NOT EXISTS`，或在子查询中 `WHERE col IS NOT NULL`。

**6. 插入失败后主键出现空洞**
序列的 `nextval` 不受事务回滚影响，回滚不会退还已取的值。→ 这是正常行为，不要试图"修复"连续性；确实需要连续编号只能用业务层生成。

**7. 加了索引却不走**
列被函数包裹、类型不匹配（`bigint = '123'` 之外的隐式转换）、前导通配 `LIKE '%x'`。→ 用 `EXPLAIN` 确认，建表达式索引或改写条件。

**8. `count(*)` 很慢**
PG 没有行数缓存，`count(*)` 必须扫描（走索引时可只扫索引）。→ 大表用估算：`SELECT reltuples::bigint FROM pg_class WHERE relname='t';` 或维护计数表。

**9. 浮点数比较不相等**
`0.1 + 0.2 <> 0.3` 在 `float8` 下为真。→ 金额用 `numeric`；必须比较浮点时用 `abs(a-b) < 1e-9`。

**10. 长事务导致表越来越大**
`idle in transaction` 持有旧快照，VACUUM 无法回收死元组。→ 监控 `pg_stat_activity.xact_start`，应用层事务要短；连接池必须配 `idle_in_transaction_session_timeout`。

**11. `jsonb` 字段比较永远为假**
`payload -> 'a'` 返回 `jsonb`，与字符串 `'1'` 比较类型不匹配。→ 取值用 `->>`，比较用 `(payload ->> 'a')::int`。

**12. 更新一列却锁了整表**
无索引的 `UPDATE ... WHERE` 会对全表加行锁并扫描全表，长事务下阻塞所有人。→ 更新条件列必须建索引，分批提交（`LIMIT` + 循环）。

**13. `ORDER BY` 写在子查询里无效**
子查询的输出顺序不保证，外层不写 `ORDER BY` 时返回顺序不确定。→ 排序只写在最外层。

**14. `LIMIT` 不配 `ORDER BY` 结果随机**
无排序时 `LIMIT 10` 返回哪 10 行由执行计划决定。→ 分页必须带确定性排序（末尾补主键，避免并列导致翻页重复）。

**15. `count(col)` 比 `count(*)` 少**
`count(col)` 忽略 NULL。→ 统计行数用 `count(*)`，统计非空值才用 `count(col)`。

**16. 加列后旧代码插入失败**
新列设了 `NOT NULL` 但没有默认值。→ 先加可空列，回填数据后再 `SET NOT NULL`。

**17. 索引越多写入越慢**
每个索引都要在 INSERT/UPDATE/DELETE 时维护。→ 定期用 `pg_stat_user_indexes.idx_scan = 0` 找无用索引并清理。

**18. `VACUUM FULL` 把业务卡死**
它持有 `ACCESS EXCLUSIVE` 锁并重写整表。→ 生产大表用 `pg_repack`，或选低峰期执行。

**19. 时区转换做了两次**
`timestamptz AT TIME ZONE 'UTC'` 返回的是**不带时区**的 `timestamp`，再加偏移会重复换算。→ 转换只在边界做一次，内部全程 `timestamptz`。

**20. 连接池耗尽导致应用全挂**
`max_connections` 是硬上限，超了直接拒绝连接。→ 应用侧用 PgBouncer（`transaction` 模式），并把 `idle_in_transaction_session_timeout`、`statement_timeout` 都设上。

## 12. 一页速查

| 目的 | 命令 |
|---|---|
| 连库 | `psql -h H -p 5432 -U U -d DB` |
| 切库 | `\c dbname` |
| 看表结构 | `\d tablename` |
| 纵向显示 | `\x` |
| 计时 | `\timing` |
| 建表自增 | `id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY` |
| 加列 | `ALTER TABLE t ADD COLUMN c text;` |
| 改类型 | `ALTER TABLE t ALTER COLUMN c TYPE int USING c::int;` |
| 建索引 | `CREATE INDEX CONCURRENTLY idx ON t (col);` |
| 看计划 | `EXPLAIN (ANALYZE, BUFFERS) SELECT ...;` |
| 更新统计 | `ANALYZE t;` |
| 回收空间 | `VACUUM t;` |
| upsert | `INSERT ... ON CONFLICT (k) DO UPDATE SET c = EXCLUDED.c;` |
| 拿回自增 | `INSERT ... RETURNING id;` |
| 关联更新 | `UPDATE a SET c = b.c FROM b WHERE a.id = b.aid;` |
| 关联删除 | `DELETE FROM a USING b WHERE a.id = b.aid;` |
| 每组首条 | `SELECT DISTINCT ON (k) * FROM t ORDER BY k, ts DESC;` |
| 组内排名 | `row_number() OVER (PARTITION BY k ORDER BY x DESC) = 1` |
| 环比 | `lag(x) OVER (ORDER BY d)` |
| 累计 | `sum(x) OVER (ORDER BY d ROWS UNBOUNDED PRECEDING)` |
| 条件计数 | `count(*) FILTER (WHERE status='paid')` |
| 展开 JSON | `jsonb_array_elements_text(data->'arr')` |
| 取 JSON 值 | `data ->> 'key'`（文本）、`data -> 'key'`（jsonb） |
| JSON 包含 | `data @> '{"a":1}'` |
| 展开数组 | `unnest(arr)` |
| 时间截断 | `date_trunc('day', ts)` |
| 时间差 | `age(ts2, ts1)`、`ts2 - ts1` |
| 安全除法 | `a / NULLIF(b, 0)` |
| 兜底空值 | `COALESCE(a, b, 0)` |
| 队列取任务 | `ORDER BY id LIMIT 1 FOR UPDATE SKIP LOCKED` |
| 查活动会话 | `SELECT * FROM pg_stat_activity WHERE state <> 'idle';` |
| 查阻塞 | `SELECT pid, pg_blocking_pids(pid) FROM pg_stat_activity;` |
| 杀查询 | `SELECT pg_cancel_backend(pid);` |
| 查表大小 | `SELECT pg_size_pretty(pg_total_relation_size('t'));` |
| 备份 | `pg_dump -Fc -d DB -f x.dump` |
| 恢复 | `pg_restore -d DB -j 4 x.dump` |
| 客户端导 CSV | `\copy t TO 't.csv' CSV HEADER` |
